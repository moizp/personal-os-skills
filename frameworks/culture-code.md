# Framework: The Culture Code (Daniel Coyle)

Generic summary for use by Skills. Most relevant when this system is
applied to a team's shared goals/todos, not purely individual planning.

## Core ideas relevant to planning

- **Belonging cues.** Team processes (reviews, standups, planning) should
  visibly signal inclusion — e.g. explicit turn-taking, acknowledging
  contributions — not just transact tasks.

- **Vulnerability loops.** Psychological safety is built when people
  admit uncertainty/mistakes and it's met with acknowledgment, not
  punishment. A team's weekly review should have room for "this didn't
  work" without it becoming a performance review.

- **Shared purpose, stated often.** High-performing teams over-communicate
  priorities and purpose, more than seems necessary. Quarterly goal-setting
  for a team should restate the "why," not just the "what."

## How this should show up in the system

- If goals/todos are shared across a team room, weekly review should
  include a lightweight "what got in the way" prompt, not just status.
- Team quarterly goals should restate purpose alongside targets.
- Not applicable to purely solo/individual use — skip this framework in
  config if you're the only person in the loop.
