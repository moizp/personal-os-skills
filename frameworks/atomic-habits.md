# Framework: Atomic Habits (James Clear)

Generic summary for use by Skills.

## Core ideas relevant to planning

- **Identity-based habits.** Frame recurring goals as "become someone who
  does X" rather than "achieve X once." Daily/weekly todos that are habit
  instances should be tagged/tracked as recurring identity votes, not
  one-off tasks.

- **The four laws of behaviour change**: make it obvious, make it
  attractive, make it easy, make it satisfying. Useful as a checklist when
  a recurring habit-todo keeps getting skipped — diagnose which law is
  broken rather than just rescheduling it.

- **Habit stacking.** New habits attach more reliably to an existing habit
  ("after I [existing habit], I will [new habit]") than to a time slot
  alone.

- **1% better, systems over goals.** The system (the recurring weekly/daily
  process) matters more than any single goal; a good review process should
  ask about the system's health, not just goal completion percentages.

## How this should show up in the system

- Recurring habit-goals get a distinct todo type from one-off project tasks.
- Weekly review should look at *streaks/consistency*, not just
  done/not-done for a given week.
- If a habit-todo is repeatedly missed, the review should prompt
  "which of the four laws is broken?" rather than just re-adding it.
